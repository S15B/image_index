# Image Search Engine — поиск изображений по тексту и контексту

Учебный проект, объединяющий парсинг HTML, сбор данных веб-краулером, нейросетевое описание изображений (BLIP-large) и построение полнотекстового инвертированного индекса с гамма‑ и дельта-сжатием Элиаса. Поисковый запрос выполняется по русскому тексту, полученному из контекста страницы и автоматически переведённых описаний. Реализован веб-интерфейс для демонстрации.

---

## Модуль 1 — HTML-парсер

Парсер извлекает из HTML-кода все возможные изображения и окружающий их текст.  
Написан **без использования сторонних библиотек** (только стандартная библиотека Python).

Файл: `html_parser.py`.

**Возможности:**
- Обнаружение изображений не только в тегах `<img src="...">`, но и в других атрибутах (`data-src`, `srcset`, `<source>`, CSS-свойствах `background-image` и т.п.).
- Извлечение контекста вокруг каждого изображения: текст до и после картинки, заголовок ближайшего раздела, текст родительского блока.
- Сохранение метаинформации в структурированном виде (JSON) для дальнейшей обработки.

Парсер используется как составная часть краулера во втором модуле.

---

## Модуль 2 — Веб-краулер

Асинхронный краулер на Python (`crawler/async_crawler.py`) обходит страницы сайтов, сохраняет найденные изображения и формирует файлы с контекстом.
В файле `crawler/start_urls.txt` необходимо написать начальные страницы (по доменам которых будет ходить краулер).

**Пример запуска со всеми аргументами:**
```bash
python crawler/async_crawler.py --max-pages 100 --workers 4 --resume
```

**Аргументы командной строки:**
- `--max-pages` - максимальное количество страниц для обхода.
- `--workers` - число параллельных потоков (по умолчанию 2).
- `--resume` - флаг, разрешающий продолжить с последнего сохранения (пропускает уже обработанные URL).

Результаты сохраняются в директорию `data/extracted_images/`. Для каждой страницы создаётся подпапка `page_<id>`, содержащая загруженные изображения и файл `results.json` с извлечённым контекстом.

## Модуль 3 — Инвертированный индекс, поиск и веб-интерфейс

### 3.0 Предварительная подготовка данных

Перед построением индексов необходимо сгенерировать описания изображений, перевести их на русский язык и объединить всю информацию в единый файл.

#### 3.0.1 Загрузка модели описания изображений

Используется модель **BLIP-large** (нейросеть для image captioning).  
Перед первым запуском генерации необходимо загрузить веса модели:

```bash
python download_model_local.py
```

#### 3.0.2 Генерация описаний

```bash
python generate_descriptions.py
```

Скрипт автоматически находит дубликаты по перцептивному хешу (phash) и подставляет уже сгенерированное описание для повторяющихся картинок, экономя вычислительные ресурсы. Результат записывается в `descriptions_index.json`.

#### 3.0.3 Перевод и объединение данных

Для обеспечения единого русского поискового пространства все описания переводятся с английского на русский, после чего все данные сливаются в один файл.

```bash
python unify_documents.py
```

Скрипт читает:
- контексты из `data/extracted_images/*/results.json`,
- описания из `descriptions_index.json`,
- выполняет перевод через GoogleTranslator (требуется интернет),

и создаёт итоговый `unified_documents.json`, в котором для каждого изображения хранятся:
- id,
- image_path,
- phash,
- source_url,
- context (русский текст со страницы),
- description_en (исходное описание),
- description_ru (переведённое описание).

### 3.1 Построение индексов

Строится три варианта инвертированного индекса:
- только по контексту (`context`),
- только по описанию (`description`),
- по обоим полям (`full`).

Для каждого варианта доступны три метода хранения списков документов:
- без сжатия (`none`),
- гамма-код Элиаса (`gamma`),
- дельта-код Элиаса (`delta`).

Таким образом, общее число индексов — 9.

Команда для построения:

```bash
python index/main.py build
```
Индексы и токенизатор сохраняются в `data/index/` (файлы `.pkl`).
Для оценки размеров и скорости поиска выполните:

```bash
python index/main.py test
```

### 3.2 Дедупликация результатов

В модуле `index/dedup.py` реализованы функции удаления дубликатов из поисковой выдачи по двум критериям:
- одинаковый перцептивный хеш (`phash`),
- одинаковый исходный URL (`source_url`).

Дедупликация применяется автоматически при поиске через веб-интерфейс.

### 3.3 Веб-интерфейс

Демонстрационное Flask-приложение позволяет в реальном времени искать изображения и сравнивать влияние сжатия.

Запуск:
```bash
python -m web.app
```
После старта интерфейс доступен по адресу http://127.0.0.1:5000.

Функциональность:
- Выбор области поиска: везде / только контекст / только описание.
- Выбор метода сжатия (без сжатия, гамма, дельта).
- Отображение времени выполнения запроса.
- Дедупликация результатов по phash и исходному URL.
- Предпросмотр найденных изображений с фрагментами текста.

## Зависимости и установка

Все необходимые библиотеки перечислены в `requirements.in`. Для установки запустите 

```bash
pip install -r requirements.in
```

Особенность для `PyTorch`: если вы не планируете использовать GPU (CUDA) для генерации описаний, удалите первую строку в `requirements.in` и установите стандартную версию `torch` вместо `torch-gpu`.
